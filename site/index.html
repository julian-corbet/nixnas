nixnas

An encrypted NixOS NAS appliance, booted from RAM

Turn any NixOS config into a USB-bootable, RAM-resident, LUKS-encrypted NAS that survives a bad update and a missing disk — the Unraid operating model, fully declarative.

How it works

1

Declare

Your host's nixosConfiguration imports the nixnas module and sets a handful of nixnas.* values. k3s, GPU, Samba, VMs are plain NixOS alongside.

2

Build & flash

A small Rust TUI builds the image locally, signs it with your own Secure Boot keys, and flashes the stick. Nothing leaves your machine.

3

Boot

Encrypted, RAM-resident, headless. One PIN unlocks the store and every data pool. A bad update? Boot the previous generation from the menu.

Features

RAM-resident, done right

The root is a tmpfs (impermanence); only /nix and the ESP persist. The booted closure is warmed into a compressed page cache — run-from-RAM without copytoram, and self-update still works.

Encrypted f2fs store

The on-stick store is LUKS2 with f2fs zstd:22 compression — small footprint on a slow stick, fast once it's in RAM.

Secure Boot, your keys

lanzaboote signs every Unified Kernel Image with your own PK/KEK/db. The Microsoft CA is not enrolled — no unsigned kernel runs.

TPM2 + PIN unlock

The store key is released only when the boot chain measures clean and the PIN is entered — every boot, by design. A mandatory recovery keyslot is the fallback.

Headless remote unlock

No console? The NIC comes up in the initrd and you hand the PIN over SSH. Validated unlocking the box entirely over the network.

Rollback-safe

Every past generation stays bootable as its own signed UKI; the bootloader menu is the guaranteed rollback, with boot-counting on top. A failed update never strands you.

Self-update, never self-reboots

autoUpgrade stages the next generation and stops — it activates on your next PIN-unlocked reboot, so a headless box is never stuck at an unlock prompt.

Your data pools, untouched

nixnas imports and unlocks the ZFS pools you built; it never creates, formats, or destroys them. The box boots even if a pool is degraded or missing.

Kind to the stick

Logs, /tmp, coredumps and swap live in RAM, so the USB takes ~no writes except updates — measured at 60 KiB for ~100 MiB of activity. Cheap sticks don't wear out.

Portable disks

Only the stick binds to the TPM. The data pools take a plain passphrase keyslot, so a disk pulled into any machine still opens — no specific box's TPM required.

Tuned kernel

The CachyOS kernel (x86-64-v3 + ThinLTO) with zfs_cachyos, pulled pre-built from a binary cache — speed without a local compile.

Thin by design

nixnas owns boot, crypto, the USB store, and kernel packaging — nothing else. Your k3s, GPU, shares and VMs are plain NixOS you declare alongside.

Architecture

  USB stick  (write-isolated)               ZFS pools  (imported, never formatted)
  ┌────────────────────────────┐            ┌───────────────────┬───────────────────┐
  │ ESP    signed UKIs (rollbk) │            │  HOT   (SSD)      │  COLD   (HDD)      │
  │ LUKS2  f2fs-zstd store ──┐  │            │  images · state   │  bulk · backups   │
  └──────────────────────────┼──┘            └─────────▲─────────┴─────────▲─────────┘
        unlock once (TPM2+PIN)│  over SSH               │  same passphrase  │
                              ▼  in the initrd          │  (keyring reuse)  │
                   root = tmpfs (RAM)  ◄── /nix warmed into compressed RAM ─┘
                              │
                   k3s · samba · VMs  ── workloads pulled from Git at runtime (not on the stick)

Impermanence

The root is a tmpfs; only /nix and the ESP survive a reboot. The OS runs from RAM — the slow stick is spared, runtime state lives on the pools.

One unlock, everything

The PIN is the TPM2 PIN and the data-pool passphrase. Entered once in the initrd, reused across the store and every pool via the kernel keyring.

Import-only

nixnas unlocks and imports your existing pools. It never creates, formats, or destroys them — the only device it ever partitions is the USB stick.

Get started

Scaffold a private host

nixnas is the public core; your real disks, keys and pools live in a private overlay that imports it:

nix flake init -t github:julian-corbet/nixnas#host

Fill in your nixnas.* values in host.nix — pools, SSH keys, the USB device.

Build & flash

The Rust TUI builds the personalised image on your trusted machine and flashes the stick:

cd tui && cargo run
# → builds .#image, prompts the passphrase,
#   flashes via caligula

Requirements

A UEFI x86-64 box with TPM 2.0, a ≥8 GiB USB stick, and your own ZFS data pools whose LUKS members carry the chosen passphrase as a keyslot. Secure Boot needs your own keys enrolled + a firmware password.

Status. Built and validated end to end in a VM (QEMU / OVMF / swtpm): the CachyOS kernel, impermanence, the LUKS f2fs-zstd store, lanzaboote Secure Boot, TPM2 + PIN, headless initrd-SSH unlock, rollback and self-update all boot in one image. Hardware bring-up — Secure-Boot key enrolment on real UEFI, the boot-counting bless loop, the firmware password and the TPM2-NV anti-rollback counter — is the next step. See the architecture notes.
